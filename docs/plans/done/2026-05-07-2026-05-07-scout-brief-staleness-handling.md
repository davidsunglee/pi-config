# Improve scout brief staleness handling in generate-plan — implementation plan

**Source:** `TODO-47e448ec`
**Spec:** `docs/specs/2026-05-07-scout-brief-staleness-handling.md`

## Goal

Replace `generate-plan/SKILL.md` Step 1b's single SHA-mismatch warning with a path-classifier that distinguishes expected workflow drift (intervening commits touch only `docs/briefs/`, `docs/specs/`, `docs/todos/`, `docs/plans/`) from real source/config drift. Workflow-only drift is auto-handled with an informational message; non-workflow drift surfaces a `(c) Continue / (x) Stop` checkpoint menu before plan generation proceeds. Uninspectable cases (missing/malformed brief SHA, brief SHA not reachable from HEAD, git failure) unify into the same menu so behavior is uniform any time the classifier cannot prove the brief is fine. The path allowlist is extracted into a small shared reference at `agent/skills/_shared/workflow-artifact-paths.md` so future consumers stay consistent with one source of truth.

## Architecture summary

- **New shared reference doc** at `agent/skills/_shared/workflow-artifact-paths.md` — sibling of the existing `agent/skills/_shared/model-tier-resolution.md` and `agent/skills/_shared/coordinator-dispatch.md`. The doc names the four allowlist prefixes, the prefix-as-directory-boundary matching rule, and the consumers that use the allowlist. It does not define the SHA classifier.
- **Surgical edit** to `agent/skills/generate-plan/SKILL.md` Step 1b — replace the existing `Staleness check (informational only):` sub-block (which emits a single warning on SHA mismatch and a softer warning on unreadable preamble) with a classifier-based flow that references the new shared allowlist by path. The classifier reads the brief's `Git SHA:`, compares to current HEAD, enumerates intervening file paths via NUL-separated git output, classifies each path against the shared allowlist, and produces one of three outcomes: silent continue (SHA == HEAD), informational workflow-drift message + auto-continue (mismatch with workflow-only paths), or `(c)/(x)` menu (mismatch with at least one non-workflow path, OR any uninspectable case).
- **No other files change.** The constraints in the spec explicitly forbid extending the same classifier to `refine-plan`, `plan-reviewer`, `define-spec`, or `planner`; forbid changing the scout's `(o)/(k)` overwrite-or-keep prompt; forbid changing the existing brief-not-found path; and forbid extracting the SHA classifier itself to `_shared/` (only the allowlist is extracted).

The classifier lives entirely inside Step 1b's preamble extraction. Steps 2–5 of `generate-plan/SKILL.md` are unchanged. The brief file is still passed to the planner by path via `{SCOUT_BRIEF}` — staleness handling does not alter the path-based handoff contract.

## Tech stack

- Markdown contracts only. No new TypeScript or extension code.
- Targets the existing `pi-interactive-subagent` runtime's interactive-pause primitive (the same primitive `define-spec` Step 5 already uses for `(c)/(r)/(x)` menus).
- Reuses `git rev-parse HEAD` and `git diff --name-only -z <brief-sha>..HEAD` (NUL-separated output) for SHA comparison and file enumeration.
- References the existing `Scout brief: docs/briefs/<filename>` provenance contract; preamble keys (`Git SHA:`) come from `agent/skills/scout/scout-prompt.md`'s brief format.

## File Structure

- `agent/skills/_shared/workflow-artifact-paths.md` (Create) — Short reference doc. Contains: a one-paragraph description of the allowlist's purpose; the four allowlist prefix entries (`docs/briefs/`, `docs/specs/`, `docs/todos/`, `docs/plans/`) verbatim; the prefix-as-directory-boundary matching rule with positive and negative examples; the consumers list (initial entry: `agent/skills/generate-plan/SKILL.md` Step 1b); an instruction directing future consumers to add themselves to the list when they adopt the allowlist.
- `agent/skills/generate-plan/SKILL.md` (Modify) — Step 1b's existing `Staleness check (informational only):` sub-block (currently three sub-bullets: bounded preamble read, mismatch warning, unreadable preamble warning) is replaced by a classifier-based flow. The new flow: (1) bounded preamble read; (2) compute current HEAD; (3) silent continue when SHAs equal; (4) on mismatch, enumerate `<brief-sha>..HEAD` files via NUL-separated git output and classify each path against the shared allowlist; (5) emit the verbatim workflow-drift informational message when all paths are under the allowlist OR present the verbatim mixed-changes menu when any path is outside; (6) unify three uninspectable sub-cases (missing/malformed SHA, SHA not reachable from HEAD, git command failure) into the same `(c)/(x)` menu with adapted bodies; (7) handle menu responses with letter shortcut and word aliases (mirroring `define-spec` Step 5); (8) emit the terminal stop-message and halt on `(x)`. The brief-not-found warning (`Scout brief referenced in spec not found at <path> — proceeding without it.`) is preserved verbatim. Steps 2–5 of the skill are unchanged.

- **Allowlist drift between the shared doc and the workflow-drift informational message body.** The verbatim message in Task 2 lists the four allowlist directories inline (`docs/briefs/`, `docs/specs/`, `docs/todos/`, `docs/plans/`). No code-level guard prevents drift — this is a policy/review concern. Documented in Task 2 Step 7's verbatim message text and Task 1 Step 6's self-review check that both lists match.

- **NUL-separated parsing footgun.** `git diff --name-only -z` emits paths separated by NUL bytes, NOT newlines. A naive whitespace tokenizer would split paths with spaces ("foo bar.md" → "foo" + "bar.md") and miss the boundary. Task 2 Step 5 explicitly names "NUL separation is load-bearing" and forbids whitespace tokenizing. Mitigation: the documented worker reads the SKILL.md text and uses NUL-aware parsing in implementation; the spec acceptance criterion for renames/deletions/spaces enforces this at review time.

- **Sub-case B detection ambiguity.** Distinguishing "SHA is well-formed but unknown to git" (sub-case B) from "any other git failure" (sub-case C) requires checking the specific failure mode of `git diff` or `git rev-list`. The spec does not mandate one detection method, only that the two sub-cases are distinguished. Task 2 Step 10 names `git rev-list --quiet <brief-sha>` non-zero exit OR `git diff`'s unknown-revision error class as detection candidates. Mitigation: the verbatim menu body for both sub-cases is byte-equal in option lines, so misclassifying sub-case B as sub-case C (or vice versa) only changes the body text — the user still gets the same `(c)/(x)` choice. Worst case is suboptimal explanatory text, not a behavioral bug.

- **Verbatim-string footgun across four menu variants.** The spec's "byte-equal across all four menu variants" constraint on the option lines is fragile: a stray space, a different em-dash character (`—` vs `--`), or a different bold delimiter (`**` vs `__`) breaks byte-equality. Task 2's Step 15 self-review and the acceptance criterion's `grep` count of exactly four matches per option line catch this at verification time. Mitigation: the worker copy-pastes the option lines from one source rather than retyping them, and the verifier confirms four exact matches with the same regex.

- **Brief-not-found path conflated with brief-stale path.** The two paths are independent per the spec — brief-not-found preserves today's soft warning and continues, while brief-stale fires the new classifier only when the brief exists on disk. Task 2's Steps 13 and 15 explicitly check the brief-not-found warning sits ABOVE the staleness-classifier sub-block, ordering the conditional check correctly. Mitigation: the existing list ordering in Step 1b already places brief-not-found before the (now-removed) staleness check; the replacement preserves that ordering.

- **Step 1b list-bullet indentation footgun.** The new classifier flow nests four levels deep in the bulleted list (Step 1b's inner sub-bullets, the `Scout brief: docs/briefs/<filename>` rule, the staleness classifier, the sub-case bodies). Markdown renderers vary in how they handle 4+ levels of nesting. Mitigation: Task 2's Step 15 self-review re-reads the rendered structure; the acceptance criteria target prose content (not bullet depth), so rendering differences do not break verification. Residual risk: a worker that flattens nesting may produce a structurally different list. The documented step-by-step structure in the plan keeps this contained.
