## Context

`agent/skills/execute-plan/SKILL.md` has grown several mechanical, repeatable, or safety-sensitive procedures inline. Extracting the right pieces into tested helpers would make the skill shorter, less fragile, and easier for agents to execute consistently.

## Priority order: correctness, safety criticality, robustness

1. **Plan validation and dependency wave grouping**
   - Highest correctness value: a malformed plan should be rejected before any code is written.
   - Extend `agent/skills/execute-plan/scripts/extract-plan-tasks.py` or add a dedicated validator.
   - Validate required top-level sections, contiguous task numbering, dependency references, dependency cycles, complete `Verify:` recipes, and optional `## Test Command` extraction.
   - Emit dependency waves/sub-waves so Step 5 is deterministic and tested.

2. **Integration regression reconciliation helper**
   - Highest regression-safety value: this decides whether a branch has introduced new test failures and whether final completion is allowed.
   - Extract repeated set arithmetic from Steps 7, 12, 14, and 16.
   - Candidate path: `agent/skills/_shared/scripts/reconcile-test-run.py`.
   - Inputs: parsed test-runner artifact plus frozen baseline failures.
   - Outputs: `current_failing_stable`, `current_non_reconcilable`, `current_non_baseline_stable`, pass/fail classification, and possibly exact summary text.

3. **Shared git workspace probe**
   - High safety value: prevents accidental work on the wrong branch/workspace and makes dirty-workspace handling consistent.
   - Extract Step 0's git repository / worktree / feature-branch / dirty-status detection.
   - Candidate path: `agent/skills/_shared/scripts/git-workspace-status.py`.
   - Should be read-only and emit JSON, e.g. `is_git_repo`, `workspace_path`, `is_worktree`, `current_branch`, `branch_label`, `is_feature_branch`, `dirty_status`.
   - Keep policy decisions in `SKILL.md`; helper only reports facts.

4. **Verifier file-set computation helper**
   - High verification robustness value: the worker being judged must not be able to narrow the verifier's view of changed files.
   - Extract Step 11.2's union rule into `agent/skills/execute-plan/scripts/compute-verifier-file-set.py`.
   - Inputs: task-declared files, worker-reported files, observed git status/diff, and wave shape.
   - Output: deduplicated verifier-visible file set per task.

5. **Shared test command detection**
   - Moderate-to-high safety value: determines whether integration tests are enabled when a plan omits `## Test Command`.
   - Extract Step 3 fallback detection into something like `agent/skills/_shared/scripts/detect-test-command.py`.
   - Useful for `execute-plan`, `using-git-worktrees`, `finishing-a-development-branch`, and review/finalization workflows.
   - Should parse `package.json` properly for a `test` script.

6. **Coder report parser**
   - Robustness value: makes status handling less dependent on ad hoc reading of `results[i].finalMessage`.
   - Add `agent/skills/execute-plan/scripts/parse-coder-report.py`.
   - Parse worker status (`DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`), files changed, concerns, needs, and blocker text from worker reports.
   - Reduces fragility in Steps 9 and 10, though most of Step 10 remains interactive policy and should stay in `SKILL.md`.

## Lower-priority candidates

- Existing output-file scan from Step 4.
- Wave commit-message formatting from Step 12.
- Retry-budget bookkeeping from Step 13, if agents continue to mishandle it.

## Non-goals

Do **not** extract interactive menus, escalation choices, or high-level workflow ordering. Those are orchestration policy and should remain in `SKILL.md`.

## Acceptance criteria

- Each extracted helper has focused unit tests.
- `execute-plan/SKILL.md` delegates mechanical work to helpers while retaining policy decisions.
- Shared helpers live under `_shared` only when at least two workflows can reasonably consume them.
- Helper outputs are structured and stable enough for orchestrator use.
