## Problem

In the `clean context` session, the full workflow (`define-spec` → `generate-plan` → `execute-plan`) succeeded, but the `plan-refiner` coordinator hit several recoverable script-call errors during the `refine-plan` step invoked by `generate-plan`.

Observed errors included:

1. `fill-template.py` was called with inline JSON as the `--placeholders-json` argument, which the helper interprets as a filename.
2. `mktemp /tmp/review-plan-prompt.XXXXXX.md` failed on macOS/BSD `mktemp` semantics.
3. An ad hoc verdict parser split `**Verdict:** Not approved` incorrectly, producing `** Not approved`.
4. The coordinator tried `agent/skills/refine-plan/scripts/validate-review-provenance.py`, but the actual helper lives at `agent/skills/_shared/scripts/validate-review-provenance.py`.

The agent recovered in each case, but the errors indicate the protocol currently relies too much on model-generated shell/Python glue from prose instructions.

## Proposed solution

Move the fragile choreography into tested helper scripts so `plan-refiner` mostly runs deterministic commands instead of inventing glue.

### 1. Add review-prompt preparation helper

Create something like:

```text
agent/skills/refine-plan/scripts/prepare-plan-review-prompt.py
```

Inputs:
- plan path
- task/source/scout provenance fields
- original spec inline file/path
- structural-only note file/path
- era number
- review output base path
- working directory
- resolved reviewer model + cli

Output JSON:

```json
{
  "prompt_path": "...",
  "review_path": "...",
  "reviewer_provenance": "**Reviewer:** openai-codex/gpt-5.5 via pi"
}
```

Use Python `tempfile` internally instead of shell `mktemp`. Use the shared template-filling semantics internally so the coordinator does not call `fill-template.py` directly.

### 2. Add review-artifact validation/parser helper

Create something like:

```text
agent/skills/refine-plan/scripts/validate-and-parse-plan-review.py
```

Responsibilities:
- Validate `REVIEW_ARTIFACT:` handoff marker.
- Enforce expected review path.
- Check artifact exists and is non-empty.
- Check first non-empty line exactly matches supplied `REVIEWER_PROVENANCE`.
- Run or reuse `_shared/scripts/validate-review-provenance.py`.
- Parse `**Verdict:**` robustly.
- Count Critical / Important / Minor findings.
- Extract blocking Critical + Important findings markdown for planner edit pass.

Output normalized JSON, e.g.:

```json
{
  "review_path": "...",
  "verdict": "Not approved",
  "critical_count": 2,
  "important_count": 1,
  "minor_count": 0,
  "blocking_findings_markdown": "..."
}
```

### 3. Add planner edit-prompt preparation helper

Create something like:

```text
agent/skills/refine-plan/scripts/prepare-plan-edit-prompt.py
```

Inputs:
- blocking findings markdown
- plan artifact line
- task/source/scout provenance fields
- original spec inline file/path
- output plan path

Output JSON with a `prompt_path`.

### 4. Update protocol docs/prompts

Update `agent/skills/refine-plan/refine-plan-prompt.md` and related docs so the plan-refiner protocol says:

- Use the new helpers for prompt preparation and review validation/parsing.
- Do not hand-roll `mktemp`, direct placeholder JSON plumbing, verdict parsing, or provenance-helper paths.
- Surface helper failure JSON verbatim through the existing `STATUS: failed` taxonomy.

### 5. Test coverage

Add helper tests with fixtures covering:

- Review with `**Verdict:** Approved`.
- Review with `**Verdict:** Approved with concerns` and Important findings.
- Review with `**Verdict:** Not approved` and Critical/Important findings.
- `_None._` severity sections.
- Bad/missing provenance line.
- Missing `REVIEW_ARTIFACT:` marker.
- Path mismatch.
- Missing/empty artifact.
- macOS-safe temp file creation (no shell `mktemp` dependency).

## Success criteria

- A future `generate-plan` → `refine-plan` run does not require ad hoc recovery for template filling, temp files, verdict parsing, or provenance helper paths.
- The plan-refiner prompt contains concrete helper invocations instead of prose that requires inventing shell/Python glue.
- Helper tests cover the failure modes observed in `clean context`.
