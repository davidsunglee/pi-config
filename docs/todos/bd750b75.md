## Context

This todo was originally written after a `generate-plan` → `refine-plan` run where the `plan-refiner` coordinator had to recover from several fragile script-call mistakes.

Since then, part of that scope has already landed:

- `refine-plan` now uses the shared `parse-artifact-handoff.py` helper for `REVIEW_ARTIFACT:` marker/path/existence validation.
- The provenance-validator path is corrected to `agent/skills/_shared/scripts/validate-review-provenance.py`.
- Coordinator dispatch resolution is standardized through `agent/skills/_shared/coordinator-dispatch.md`.

Those fixes should not be re-done by this todo.

## Remaining problem

The remaining weakness is that `plan-refiner` still depends on prompt-level/manual glue for several coordinator tasks that should be deterministic and tested:

1. preparing review prompts and temp output paths
2. parsing validated review artifacts into verdict/count/findings data
3. preparing planner edit prompts from blocking findings

Today the protocol still describes some of this as step-by-step shell/text manipulation inside `refine-plan-prompt.md`, including direct `fill-template.py` usage in the fallback path and hand-parsing of the `**Verdict:**` line. That leaves too much room for model-generated glue mistakes even though the surrounding protocol is now stricter.

## Proposed solution

Move the remaining fragile choreography into dedicated helper scripts under `agent/skills/refine-plan/scripts/`.

### 1. Add review-prompt preparation helper

Create:

```text
agent/skills/refine-plan/scripts/prepare-plan-review-prompt.py
```

Responsibilities:
- accept the plan/provenance/spec/structural-only inputs already assembled by `refine-plan`
- accept the resolved reviewer `model` + `cli`
- build the exact `**Reviewer:** <provider>/<model> via <cli>` line
- compute the era review output path
- write the filled reviewer prompt to a temp file using Python `tempfile` rather than shell `mktemp`

Output JSON should include at least:

```json
{
  "prompt_path": "...",
  "review_path": "...",
  "reviewer_provenance": "**Reviewer:** openai-codex/gpt-5.5 via pi"
}
```

### 2. Add review-artifact validation/parser helper

Create:

```text
agent/skills/refine-plan/scripts/validate-and-parse-plan-review.py
```

Responsibilities:
- validate `REVIEW_ARTIFACT:` handoff using the shared artifact-handoff contract
- enforce the expected review path
- check artifact exists and is non-empty
- check the first non-empty line exactly matches the supplied `REVIEWER_PROVENANCE`
- invoke or reuse `_shared/scripts/validate-review-provenance.py`
- parse `**Verdict:**` robustly
- count Critical / Important / Minor findings
- extract blocking Critical + Important findings markdown for the planner edit pass

Output normalized JSON should include at least:

```json
{
  "review_path": "...",
  "verdict": "Not approved",
  "critical_count": 2,
  "important_count": 1,
  "minor_count": 0,
  "blocking_findings_markdown": "..."
}
```

### 3. Add planner edit-prompt preparation helper

Create:

```text
agent/skills/refine-plan/scripts/prepare-plan-edit-prompt.py
```

Responsibilities:
- accept blocking findings markdown
- accept plan/provenance/spec inputs already in the coordinator prompt
- fill the planner edit template deterministically
- write the filled edit prompt to a temp file and return its path

Output JSON should include at least a `prompt_path`.

### 4. Update protocol docs/prompts to use the helpers

Update `agent/skills/refine-plan/refine-plan-prompt.md` and related docs so the coordinator protocol says:

- use the new helpers for prompt preparation and review validation/parsing
- do not hand-roll temp-file creation, placeholder wiring, or verdict parsing in prompt prose
- surface helper failure JSON through the existing `STATUS: failed` taxonomy rather than inventing new ad hoc recovery logic

## Non-goals

Do not spend this todo on work that is already done:

- re-adopting shared `parse-artifact-handoff.py`
- re-fixing the `validate-review-provenance.py` path
- reworking the shared coordinator dispatch chain

Also out of scope:

- changing the review rubric itself
- broad refactors outside `refine-plan` unless required to support these helpers
- adding inline-review fallbacks or loosening current failure behavior

## Test coverage

Add helper tests and fixtures covering at least:

- review with `**Verdict:** Approved`
- review with `**Verdict:** Approved with concerns` and Important findings
- review with `**Verdict:** Not approved` and Critical/Important findings
- `_None._` severity sections
- bad or missing provenance line
- missing `REVIEW_ARTIFACT:` marker
- path mismatch
- missing/empty artifact
- macOS-safe temp-file creation behavior (no shell `mktemp` dependency)

## Success criteria

- A future `generate-plan` → `refine-plan` run does not require ad hoc recovery for review-prompt preparation, temp-file handling, verdict parsing, or blocking-findings extraction.
- The `plan-refiner` protocol references concrete helper invocations instead of prose that requires inventing shell/Python glue.
- The new helpers have regression tests for the failure modes that previously required coordinator recovery.
