## Goal

Update the `execute-plan` plan validator/parser so intentionally inserted task headings like `### Task 15a — CLI entry` are accepted, while malformed task headings remain rejected.

## Context

A generated plan for `pi-gondolin-sandbox` split the CLI entrypoint into `Task 15a` to avoid a dependency cycle between parser/types, command handlers, and `src/cli.ts`. The plan itself is structurally reasonable, but `agent/skills/execute-plan/scripts/extract-plan-tasks.py` currently only accepts integer task IDs via `TASK_HEADING_RE = r"^### Task (\d+)\s*[:—–-]\s*(.*)$"` and then converts task numbers with `int(...)`. As a result, `Task 15a` is reported as `malformed_task_heading` even though the heading uses an accepted separator and expresses a legitimate inserted task.

## Proposed minimal change

- Introduce a shared task-id pattern that accepts integer IDs plus a single optional lowercase alphabetic suffix, e.g. `1`, `2`, `15a`.
- Update task heading and dependency parsing to use that task-id pattern.
- Stop unconditionally converting task IDs to integers; preserve IDs like `15a` as strings where needed.
- Add a small sort/order key that orders IDs by numeric prefix and optional suffix.
- Relax the contiguous-order check to allow inserted suffix tasks only when their base integer task exists, e.g. `1, 2, 2a, 3` is valid but `1, 2a, 3` is invalid unless `2` is present.
- Keep malformed headings like `### Task 1Title` and `### Task 1` rejected.

## Acceptance Criteria

- `extract-plan-tasks.py` accepts a plan containing `### Task 15a — CLI entry (...)` and includes the task in the emitted JSON.
- Dependency lines may reference suffixed IDs if needed, e.g. `- Task 16 depends on: Task 15a`.
- Existing integer-only plans continue to parse exactly as before.
- Existing malformed-heading regression tests still pass, including no-separator and title-runs-into-digit cases.
- New regression tests cover suffixed task heading parsing, ordering/wave placement, dependency references, and malformed variants.

## Notes

Avoid a regex-only fix: accepting `15a` in the heading without updating conversion, ordering, dependency validation, and tests will either crash on `int("15a")` or misclassify inserted tasks around their base task.
