## Goal

Make Pi workflow orchestration compatible with Gondolin-backed execution by replacing ad-hoc host `/tmp` handoffs with predictable workspace-local workflow state, and by defining how recursive Pi subagents inherit the parent sandbox once `pi-interactive-subagent` supports propagation.

## Context

A transcript review of the first deep `execute-plan` run for `/Users/david/Code/pi-gondolin-sandbox` showed that the workflow itself frequently improvises paths and handoffs:

- prompts, extracted task metadata, verifier reports, and parser inputs were written under `/tmp/pi-gondolin-exec/...` and `/var/folders/...`;
- subagents were given absolute host paths such as `/Users/david/Code/...` and `/tmp/...`;
- orchestrator/subagent handoff worked because everything ran host-side, but the same flow would break when Pi data-plane tools are routed through a Gondolin guest with only the project mounted at `/workspace`;
- the model often had to infer where scratch files should live and how later agents should find them.

The workflow should make this deterministic instead of relying on each LLM turn to reconstruct the convention.

## Desired scope

### 1. Workspace-local workflow run directory

Define a canonical, gitignored workflow scratch root for skills such as `define-spec`, `generate-plan`, `execute-plan`, `refine-plan`, `refine-code`, and test-runner dispatches. Candidate shape:

```text
.pi/workflows/<run-id>/
  prompts/
  tasks/
  verify/
  reports/
  reviews/
  state.json
```

or, if we want the name to be Gondolin-specific:

```text
.pi-gondolin/workflows/<run-id>/...
```

Requirements:

- paths handed to subagents should be workspace-relative or `/workspace/...` where possible;
- scratch paths should survive across subagent sessions in the same workflow;
- transient parser inputs should live under the run directory, not host `/tmp`;
- durable artifacts may still be copied to `docs/test-runs/`, `docs/reviews/`, `docs/specs/`, or `docs/plans/` as appropriate;
- the scratch root must be gitignored by default.

### 2. Well-defined handoff protocol

Define a small workflow-state contract so the orchestrator and subagents do not have to infer locations from prompt prose:

- a run-level `state.json` with paths for plan/spec, task metadata, prompt directory, verifier output directory, test-run directory, and review output directory;
- consistent marker names and artifact path fields;
- rules for absolute host path vs workspace path vs guest path;
- cleanup policy for scratch vs durable evidence.

### 3. Recursive Pi subagent sandbox propagation

Coordinate with `pi-interactive-subagent` so Gondolin-backed parent sessions can spawn Pi-backed child sessions that inherit the sandbox boundary.

Desired behavior:

- parent Pi session records sandbox context: workspace, profile, image, allowed hosts, mount mode, trusted extensions, and tool allowlist;
- `subagent_run_*` passes that context to child Pi processes;
- child Pi sessions load the Gondolin extension and use the same workspace/image/profile constraints;
- strict mode blocks or explicitly warns for Claude-backed subagents, because Claude Code native tools are not sandboxed by the Pi extension;
- orchestrator tools remain host-side control-plane, while data-plane file/search/shell tools run in the guest.

## Non-goals

- Implementing VM-backed `grep/find/ls` in `pi-gondolin-sandbox` — tracked in that repo by TODO-86ed65cc.
- Building the custom Gondolin dev image — tracked in `pi-gondolin-sandbox` by TODO-86ed65cc.
- Sandboxing Claude Code native tools.
- Full Docker-in-Gondolin support.

## Acceptance criteria

- Workflow skills no longer write required handoff/prompt/parser scratch files to host `/tmp` by default.
- A canonical workflow run directory exists inside the project workspace and is gitignored.
- Subagent prompts receive paths that work when the project is mounted at `/workspace`.
- Test-run and review durable artifacts still land in their documented `docs/...` locations.
- `execute-plan` and `refine-code` can run without relying on host-only temp paths for required subagent handoffs.
- `pi-interactive-subagent` has a clear propagation contract for Gondolin sandbox context.
- Strict mode distinguishes host-side control-plane tools from guest-routed data-plane tools.

## Notes

This belongs in `pi-config` because it is primarily a workflow/skills orchestration convention. The corresponding tool-surface and guest-image work belongs in `pi-gondolin-sandbox`.
