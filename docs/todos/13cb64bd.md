# Goal
Create a standalone Claude Code sandbox launcher based on Anthropic Sandbox Runtime (SRT) with reusable policy profiles for interactive and AFK Claude Code workflows.

This task is intentionally independent of Gondolin, Pi, and pi-interactive-subagent. Integration with pi-interactive-subagent is a separate task.

# Motivation
SRT can wrap the whole `claude` process, so it can constrain Claude Code built-in tools, Bash child processes, MCP servers, and subagents spawned inside that process. This gives one common implementation for interactive and non-interactive Claude Code usage, including many macOS/Xcode/iOS workflows, while preserving the option to use stronger VM isolation later for high-risk work.

# Deliverables
- A convenient launch script for Claude Code under SRT, e.g. `cc-srt`, `claude-srt`, or similar.
- A policy directory with named SRT profiles, such as:
  - `interactive-default`: normal interactive Claude Code, SRT boundary, permission prompts retained.
  - `afk-coder`: disposable worktree/clone, strict read boundary, write allowed only in workspace/temp/cache paths, suitable for `--dangerously-skip-permissions`.
  - `verifier`: read-mostly, write only to temp/cache/test-output paths.
  - `xcode-ios`: macOS developer workflow profile with explicitly documented exceptions for Xcode/Simulator needs.
- A README explaining:
  - when to use each profile,
  - what is protected,
  - what holes remain,
  - why SRT is a baseline not a VM-grade boundary,
  - why Docker/SSH/cloud credential sockets should not be allowed by default.
- Smoke-test commands proving:
  - allowed workspace reads/writes work,
  - denied host secrets cannot be read,
  - denied host paths cannot be written,
  - network egress is blocked except allowed domains,
  - Claude Code can start under the wrapper.

# Policy requirements
- Default to denying broad host reads, then allow back only the current workspace and explicitly needed tool/cache paths.
- Default to allow-only writes: workspace plus narrow temp/cache paths.
- Do not expose host `~/.ssh`, cloud credentials, password manager sockets, Docker/OrbStack sockets, or unrelated home directories.
- Use a dedicated Claude Code config/auth directory where practical, rather than live host `~/.claude`.
- Avoid `allowLocalBinding` by default due to the current macOS egress-bypass concern.
- Avoid `allowAllUnixSockets` by default.
- Do not allow Docker socket by default; document that allowing it is effectively host access.
- Treat broad network domains as exfiltration channels; prefer narrow allowlists.
- For AFK `--dangerously-skip-permissions`, require disposable worktree/clone mode or a clearly named unsafe override.

# Non-goals
- No Gondolin integration.
- No Pi integration.
- No pi-interactive-subagent integration.
- No attempt to make SRT a complete substitute for Tart/Gondolin/VM isolation for hostile-code scenarios.

# Open decisions
- Repository/package name.
- Whether to publish as an npm package, keep as private scripts, or use a Homebrew/local bin install.
- Exact profile names and config file format.
- How to provision isolated Claude Code config/auth state.
- Whether to patch/work around SRT macOS `allowLocalBinding` behavior locally or simply forbid it.
- How much Xcode/iOS support belongs in the first release versus documented manual opt-in.

# Acceptance criteria
- `claude` can be launched through the wrapper with a chosen profile.
- AFK mode can run Claude Code with `--dangerously-skip-permissions` only inside the SRT profile and disposable workspace guardrails.
- Attempts to read host secrets fail in smoke tests.
- Attempts to write outside allowed paths fail in smoke tests.
- Attempts to connect to non-allowlisted network destinations fail in smoke tests.
- Documentation clearly lists remaining holes and when to escalate to VM isolation.
