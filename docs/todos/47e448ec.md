## Context

`generate-plan` currently warns whenever a spec's `Scout brief:` file has a `Git SHA:` that differs from current `HEAD`. In the normal workflow, that mismatch is expected immediately after `/scout` because the brief itself is committed after it is generated. It may also be expected after `/define-spec`, because the resulting spec/todo workflow artifacts may be committed after the brief. These expected workflow commits should not nag the user as if the brief is meaningfully stale.

## Desired behavior

When `generate-plan` sees a scout brief SHA that differs from current `HEAD`:

1. Inspect the commits after the scout brief SHA up to `HEAD`.
2. Determine the set of files affected by those commits.
3. If every affected file is under workflow-artifact paths — briefs, specs, and/or todos — treat the mismatch as expected workflow drift.
   - Examples: `docs/briefs/**`, `docs/specs/**`, `docs/todos/**`.
   - Emit an informational message that names the scout brief SHA, current HEAD, and summarizes the workflow-artifact commits/files that caused the mismatch.
   - Continue plan generation automatically.
   - Do not present a nag/warning menu for these expected commits.
4. If any affected file is outside the expected workflow-artifact paths, surface an explicit checkpoint menu before planning continues.
   - Show the scout brief SHA and current HEAD.
   - List the non-workflow files changed since the brief SHA.
   - Explain that the brief may be stale relative to source/config/agent changes.
   - Offer options using wording consistent with other workflow menus:
     - `(c) Continue with plan generation — proceed despite the scout brief / HEAD difference`
     - `(x) Stop plan generation — resolve manually before planning`

## Notes for refinement

- Use wording consistent with existing `(c)` / `(x)` menus elsewhere in the workflow.
- Define the expected workflow-artifact path allowlist precisely. Initial suggestion: `docs/briefs/`, `docs/specs/`, and `docs/todos/`.
- Consider deleted/renamed files and files with spaces in names when designing the git command/parsing.
- If the brief SHA is malformed, missing from history, or the commit range cannot be inspected, decide whether to fall back to the existing unreadable/stale warning or present the explicit menu.

## Acceptance criteria

- `generate-plan` no longer warns/nags when the only changes after the brief SHA are under `docs/briefs/`, `docs/specs/`, and/or `docs/todos/`.
- `generate-plan` presents an explicit `(c)` / `(x)` menu when non-workflow files changed after the brief SHA.
- The menu wording is consistent with the rest of the workflow and lists the relevant non-workflow file paths.
