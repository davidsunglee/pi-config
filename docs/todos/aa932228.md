## Problem

`agent/skills/execute-plan/scripts/extract-plan-tasks.py` currently treats `## ...` and `### Task ...` headings inside fenced code blocks as real markdown structure. This caused a false validation failure in `docs/plans/2026-05-08-2026-05-08-define-spec-and-artifact-handoff-fixes.md`: Task 4 contains a fenced markdown snippet with `## Completion contract`, and `find_block_end()` truncated the task block at that line, making the existing `**Model recommendation:** standard` appear outside the parsed task.

## Desired fix

Update the parser to track fenced code blocks and ignore heading-like lines while inside fences. This should apply consistently to:

- task start detection (`### Task N:`)
- task block end detection (`## ...` and `### Task N:`)
- required section validation/body scanning
- any other structure scan that can be confused by headings inside fences

Support common markdown fences: at minimum triple backticks (` ``` `); consider triple tildes (`~~~`) too.

## Regression tests

Add tests for a plan/task that contains a fenced markdown snippet with heading-like lines, e.g.:

```md
## Completion contract
### Task 999: Not a real task
```

Assertions should verify:

- the fenced headings do not create/truncate tasks
- content after the fence remains in the task block
- `**Model recommendation:** standard` after the fence is parsed correctly
- required section validation does not treat fenced headings as real sections

## Context

A temporary workaround was added to the affected plan by placing an extra `**Model recommendation:** standard` before the fenced heading. The parser should be hardened so future plans do not need this workaround.
