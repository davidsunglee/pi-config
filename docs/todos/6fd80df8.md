## Goal

Make fast-lane warn but not prompt when started on a protected branch (`main`, `master`, or `develop`). The user already chose the current branch/workspace, so fast-lane should proceed after displaying the warning.

## Context

Fast-lane Step 3 currently renders a protected-branch checkpoint with `(c) Continue on <branch>` and `(x) Stop`. This is extra friction compared with execute-plan's workspace flow, where branch/workspace choice is resolved up front and execution does not nag again just because the current branch is protected.

## Desired scope

- Update `agent/skills/fast-lane/SKILL.md` Step 3 so protected branches display a non-blocking warning and then proceed automatically.
- Keep dirty-working-tree handling unchanged; that prompt protects against mixing unrelated changes.
- Keep the no-worktree rule unchanged; fast-lane still operates in the current workspace.
- Keep post-completion behavior unchanged; on `main`/`master`/`develop`, skip branch completion and do not push.
- Update the edge-case documentation that currently says protected-branch start requires explicit confirmation.

## Acceptance criteria

- Running fast-lane on `main`, `master`, or `develop` no longer shows a `(c)/(x)` protected-branch checkpoint.
- Fast-lane still displays a clear warning that it will commit directly to the protected branch.
- Dirty working tree checkpoint behavior remains unchanged.
- Documentation no longer claims protected-branch starts require explicit confirmation.
