## Problem
Claude CLI-backed subagents running in mux terminals are not consistently calling the expected completion reporter when they finish. This makes orchestrations and parent-agent handoff unreliable because the parent may not receive the intended “done” signal.

## Goal
Improve completion-reporting reliability for Claude CLI-backed subagents in mux terminal runs by hardening prompts only.

## Scope
- Keep all changes in this `pi-config` project.
- Focus on prompt hardening.
- Do not modify `pi-interactive-subagent` for this task.
- Do not add wrapper/runtime fallback behavior yet.
- Do not change mux lifecycle watcher behavior yet.

## Target agents
Apply the prompt hardening to all subagents that can be backed by Claude CLI, except coordinator-style agents that need to launch their own subagents, such as:
- `plan-refiner`
- `code-refiner`

## Investigation notes
- Inspect the current subagent prompt definitions in `pi-config`.
- Identify all Claude CLI-compatible subagent roles.
- Confirm the expected completion MCP/tool name from `pi-interactive-subagent`; it is believed to be something like `pi_subagent_done`.
- Ensure prompts refer to the completion mechanism clearly and unambiguously.

## Implementation approach
- Strengthen relevant subagent prompts with an explicit final-step requirement to call the completion reporting tool.
- Add a compact end-of-task checklist, for example:
  1. Verify the requested work is complete.
  2. Summarize the outcome.
  3. Call the completion reporting tool, e.g. `pi_subagent_done`.
  4. Exit only after reporting completion.
- Include a negative instruction: do not merely print or describe completion; use the completion reporting tool.

## Out of scope
- Runtime fallback detection when a subagent exits without reporting.
- Parent/orchestrator behavior changes for missing completion reports.
- Automated tests.
- Changes to `pi-interactive-subagent`.

## Verification
Manual verification will be performed observationally by running Claude CLI-backed subagents in mux terminals over the next few runs and checking whether they call the expected completion reporter.

## Acceptance criteria
- Claude CLI-compatible non-coordinator subagent prompts explicitly instruct agents to call the completion reporting tool as their final completion step.
- The expected completion tool name is verified before being hardcoded into prompts.
- Prompts clearly distinguish tool-based completion reporting from merely printing a final message.
- No changes are made outside `pi-config`.
