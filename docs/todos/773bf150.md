## Problem
Claude CLI-backed subagents running in mux terminals are not consistently calling the MCP/tooling completion reporter when they finish. This makes orchestrations and parent-agent handoff unreliable, especially for autonomous roles like coders and planners.

## Goal
Improve reliability of subagent "done" signaling for Claude CLI sessions in mux terminals.

## Initial investigation targets
- Review current Claude CLI subagent prompts for coder and planner roles.
- Identify where completion-reporting instructions are placed and whether they are prominent/repeated enough.
- Compare behavior against pi-backed subagents and any agents that report reliably.
- Determine whether failures correlate with:
  - long tasks or context pressure
  - terminal/mux execution mode
  - auto-exit behavior
  - role prompt structure
  - missing/ambiguous MCP tool naming

## Possible hardening approaches
- Strengthen role/system prompts with explicit final-step requirements to call the completion MCP tool.
- Add a compact checklist near the end of coder/planner prompts: verify work, summarize, call completion tool, then exit.
- Include negative instruction: do not merely print completion; use the MCP completion tool.
- Add watchdog/terminal-output fallback detection if the CLI exits without a completion tool call.
- Add wrapper-level enforcement where possible: inject a mandatory post-task completion reminder, or detect terminal idle/exit and synthesize a structured completion status.
- Add tests or manual repro scripts for Claude CLI coder/planner subagents in mux terminals.

## Acceptance criteria
- Coder and planner Claude CLI subagents reliably report completion via the expected MCP/tooling pathway in mux terminal runs.
- Any prompt changes are documented with rationale.
- Failure fallback behavior is defined for cases where the CLI exits without calling the tool.
- Reproduction/verification steps are recorded.
