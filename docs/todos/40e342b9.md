## Summary

Several planning/execution failures came from boundary mismatches rather than substantive plan or code issues:

- human-/LLM-authored Markdown used harmless punctuation/capitalization variants that strict parsers rejected;
- LLM-authored protocol reports used Markdown heading syntax around otherwise valid status lines;
- `refine-code` failed when the expected on-disk review artifact existed but the terminal `REVIEW_ARTIFACT:` transport marker was missing;
- `generate-plan` needs safer user choices when refinement exhausts its iteration budget without approval.

The unifying goal is **targeted tolerance at human/LLM-authored boundaries, strict validation for machine-trust decisions, and clearer failure/continuation UX**.
