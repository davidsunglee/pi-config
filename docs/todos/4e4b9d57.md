## Context

Two small workflow changes are needed in this repo:

1. **Fastlane skill:** The user-facing menu currently includes `P` / "promote to deep workflow". This option does not work correctly. Remove it from the menu and related handling. Users can already choose the stop option and manually trigger the deep workflow if they want to.

2. **Generate-plan skill:** The plan artifact filename often duplicates a date when the input spec is already date-prefixed. For example, a spec named with `2026-05-19-...` can produce a plan file beginning `2026-05-19-2026-05-19-...`.

## Desired behavior

- Fastlane no longer advertises or handles the broken promote-to-deep-workflow option.
- Generate-plan should avoid duplicated date prefixes.
- When deriving a plan filename from a spec filename, strip any existing leading date prefix from the spec-derived basename, then prepend/append the current date according to the plan naming convention.
  - Example: if generating a plan today (`2026-05-19`) from a spec created yesterday (`2026-05-18-my-feature.md`), the plan filename should use today's date once, e.g. `2026-05-19-my-feature.md`, not `2026-05-19-2026-05-18-my-feature.md`.

## Acceptance criteria

- [ ] The fastlane skill documentation/workflow no longer shows `P` / promote-to-deep-workflow as a menu choice.
- [ ] Any instructions or branches that describe executing that `P` option are removed or replaced with the existing stop/manual deep workflow guidance.
- [ ] The generate-plan skill's filename instructions explicitly normalize spec-derived names by removing an existing leading `YYYY-MM-DD-` prefix before applying today's date.
- [ ] Existing naming behavior is preserved for spec names that do not already start with a date.
- [ ] The changes are documented clearly enough for future agents following the skills to produce the correct artifacts.
