## Problem

Several workflow helpers use simple line-based parsing and may confuse literal content with real protocol structure. This is the same general failure class as `TODO-aa932228` (`execute-plan` headings inside fenced code blocks), but it appears in other helpers too — especially where reports embed markdown snippets, stdout/stderr, or example marker lines.

This follow-up should track the remaining parser/handoff hardening work across `define-spec`, `generate-plan`, `execute-plan`, `refine-plan`, and `refine-code`.

## Priority order

1. **`agent/skills/execute-plan/scripts/parse-verifier-report.py`**
   - Highest priority.
   - It splits top-level `## ...` sections and Phase 1 evidence blocks using raw heading detection.
   - The verifier report intentionally embeds captured `stdout` / `stderr`, so heading-like lines or fenced markdown inside captured output can be mistaken for real report structure.
   - Harden section/evidence parsing so embedded payload text does not terminate or create sections.
   - Add regression tests with captured output containing heading-like lines and fenced markdown.

2. **`agent/skills/execute-plan/scripts/parse-coder-report.py`**
   - `_section()` currently stops on the next raw `## ...` line.
   - A coder report can include markdown snippets or pasted output inside `## Completed`, `## Tests`, `## Self-Review Findings`, or `## Concerns / Needs / Blocker`.
   - Harden section extraction so embedded heading-like content does not truncate sections.
   - Add regression tests covering fenced markdown / pasted content inside report sections.

3. **`agent/skills/refine-code/scripts/parse-refine-code-summary.py`**
   - `parse_sections()` uses raw `## ...` splitting.
   - Embedded reviewer text or copied markdown, especially in `## Remaining Issues`, could be mistaken for real section boundaries.
   - Harden section parsing so embedded heading-like content does not corrupt summary parsing.
   - Add regression tests for fenced/embedded markdown inside parsed sections.

4. **`agent/skills/_shared/scripts/parse-artifact-handoff.py`**
   - Shared helper used by `define-spec`, `generate-plan`, `refine-plan`, and `refine-code`.
   - It currently extracts the last `<MARKER>: <path>` line anywhere in the final message.
   - Quoted examples, echoed instructions, or other incidental marker-shaped text could be mistaken for a real artifact handoff.
   - Harden marker extraction rules to reduce false positives while preserving current workflow contracts.
   - Add regression tests for incidental/quoted marker lines vs real terminal handoff markers.

5. **`agent/skills/_shared/scripts/extract-provenance-preamble.py`**
   - Used by `generate-plan`.
   - In spec mode it stops scanning at the first raw `## ` heading.
   - A preamble example or fenced snippet containing heading-like lines could end the scan early.
   - Harden bounded preamble scanning so literal fenced content does not prematurely terminate parsing.
   - Add regression tests for fenced markdown in the scanned preamble region.

6. **`agent/skills/execute-plan/scripts/extract-plan-tasks.py` — `## Test Command` fence parsing follow-up**
   - Separate from `TODO-aa932228`, but same general hardening area.
   - The `## Test Command` parser still looks specifically for ````bash` ... ````, rather than the broader fence rules chosen for task parsing.
   - Align `## Test Command` fence handling with the agreed fence behavior:
     - backticks and tildes
     - fence length 3+
     - leading indentation allowed
     - closing fence must use the same marker type and be at least as long as the opener
     - unclosed opener treats the rest of the block/file as inside the fence for parsing purposes
   - Add regression tests for these cases.

## Out of scope for now

- `agent/skills/refine-plan/scripts/parse-refine-plan-summary.py` — currently parses explicit line labels rather than markdown section structure, so it does not appear susceptible to this same heading-in-fence bug class.
- `agent/skills/_shared/scripts/validate-review-provenance.py` — validates only the first non-empty line and does not appear susceptible to this same structure-confusion bug class.

## Acceptance criteria

- Each priority item is reviewed in order and hardened where needed.
- Every changed helper gets regression coverage for the specific confusion case it is vulnerable to.
- Existing workflow parser/unit tests pass after the hardening work.
- Any intentionally deferred item is documented with a concrete reason.
