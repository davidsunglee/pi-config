## Problem

Several workflow helpers use simple line-based parsing and may confuse literal content with real protocol structure. This is the same general failure class as `TODO-aa932228` (`execute-plan` headings inside fenced code blocks), but it also appears where reports embed markdown snippets, captured `stdout` / `stderr`, or example marker lines.

This todo tracks the remaining parser/handoff hardening work across `define-spec`, `generate-plan`, `execute-plan`, `refine-plan`, and `refine-code`.

## Locked scope decisions

- Keep this as **one umbrella todo**, but treat each priority item as **independently shippable** work that may land across multiple sessions/commits.
- Keep scope **narrow** to the specific bug class where embedded payload text is mistaken for real protocol/structure. Do **not** turn this into a general markdown-parser rewrite.
- Preserve embedded payload text **as verbatim as practical**. These helpers should harden structure detection, not rewrite payload content.
- If a reviewed item turns out not to need a code change, that is acceptable **only** with a concrete written reason and regression coverage where practical.

## Cross-cutting implementation requirement

Introduce a new shared fence-aware helper as a **pure Python module** under `agent/skills/_shared/scripts/`, with its own focused tests.

Constraints for that helper:

- Reuse it only where the **same logic genuinely applies**.
- Keep it **small**: a shared primitive plus shared section-splitting only where byte-equivalent behavior is truly shared.
- Do **not** grow it into a general markdown parser.
- Use one exact fence contract everywhere it applies:
  - backticks and tildes
  - fence length 3+
  - leading indentation allowed
  - closing fence must use the same marker type
  - closing fence must be at least as long as the opener
  - an unclosed opener keeps the rest of the scanned region/file inside the fence

## Priority order

1. **`agent/skills/execute-plan/scripts/parse-verifier-report.py`**
   - Highest priority.
   - Harden the helper against embedded payload text being mistaken for verifier report structure.
   - Cover **all relevant structure markers in the existing report contract** where this confusion class applies — not just top-level `## ...` sections and `[Evidence for Criterion N]` boundaries, but also other structure markers in this helper when embedded `stdout` / `stderr` or pasted markdown could mimic them.
   - Preserve the existing report contract; do **not** redesign the verifier protocol.
   - Preserve embedded payload text as verbatim as practical.
   - Add regression tests with captured output containing heading-like lines, fenced markdown, and other marker-like lines that could previously corrupt parsing.

2. **`agent/skills/execute-plan/scripts/parse-coder-report.py`**
   - `_section()` currently stops on the next raw `## ...` line.
   - Reuse the shared fence-aware helper if the same section-splitting logic applies.
   - A coder report can include markdown snippets or pasted output inside `## Completed`, `## Tests`, `## Self-Review Findings`, or `## Concerns / Needs / Blocker`.
   - Harden section extraction so embedded heading-like content does not truncate sections.
   - Preserve embedded payload text as verbatim as practical.
   - Add regression tests covering fenced markdown / pasted content inside report sections.

3. **`agent/skills/refine-code/scripts/parse-refine-code-summary.py`**
   - `parse_sections()` currently uses raw `## ...` splitting.
   - Reuse the shared fence-aware helper if the same section-splitting logic applies.
   - Embedded reviewer text or copied markdown, especially in `## Remaining Issues`, must not be mistaken for real section boundaries.
   - Preserve embedded payload text as verbatim as practical.
   - Add regression tests for fenced/embedded markdown inside parsed sections.

4. **`agent/skills/_shared/scripts/parse-artifact-handoff.py`**
   - This helper should remain **narrowly rule-based**, not generally markdown-aware.
   - Tighten extraction so a valid handoff is accepted **only** when the **exact last non-empty line** of the final message is a column-1 `<MARKER>: <path>` line.
   - Earlier marker-shaped lines must be ignored.
   - Quoted / indented / backticked marker-looking lines must **not** count as a valid handoff line.
   - Harden marker extraction rules to reduce false positives while preserving the documented workflow contract that the marker is the terminal line.
   - Add regression tests for incidental/quoted marker lines vs the real terminal handoff line.
   - Update helper `--help` / docstring / directly affected tests/docs so they match the tightened contract.

5. **`agent/skills/_shared/scripts/extract-provenance-preamble.py`**
   - Used by `generate-plan`.
   - In spec mode, keep the current bounded-scan intent: stop at the first **real** `## ` heading or line 40.
   - Harden that logic so fenced markdown or heading-like lines inside fenced content do **not** prematurely terminate the scan.
   - Reuse the shared fence-aware primitive if the same fence logic applies.
   - Add regression tests for fenced markdown in the scanned preamble region.

6. **`agent/skills/execute-plan/scripts/extract-plan-tasks.py` — `## Test Command` fence parsing follow-up**
   - Separate from `TODO-aa932228`, but part of the same hardening area.
   - Reuse the new shared fence-aware helper **if** the exact same fence contract applies.
   - Align `## Test Command` fence handling with the shared rules above.
   - When `## Test Command` contains multiple possibilities, accept the **first fenced block under that section**, regardless of info string (`bash`, empty, etc.).
   - Preserve the current lightweight parser approach; do **not** broaden this into a general markdown parser.
   - Add regression tests for backticks, tildes, 3+ fence length, leading indentation, same-marker closing, longer closing fence, unlabeled fences, and unclosed fences.

## Out of scope for now

- General markdown parsing hardening beyond the specific embedded-payload/structure-confusion bug class above.
- `agent/skills/refine-plan/scripts/parse-refine-plan-summary.py` — currently parses explicit line labels rather than markdown section structure, so it does not currently appear susceptible to this same bug class.
- `agent/skills/_shared/scripts/validate-review-provenance.py` — validates only the first non-empty line and does not currently appear susceptible to this same structure-confusion bug class.
