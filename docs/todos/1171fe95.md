## Summary

The current `define-spec` Step 8 workflow recommendation uses `agent/skills/fast-lane/scripts/recommend-workflow.py`, which is too shallow. It recommended fast lane for TODO-40e342b9 / `docs/specs/2026-05-11-harden-workflow-boundaries.md`, even though that work clearly merits `generate-plan` → `execute-plan` because it spans multiple workflow skills, parsers, artifact handoffs, trust-boundary validation, prompt contracts, and exhausted-budget UX.

Current helper behavior is essentially:

- recommend fast lane when there is no `## Approach` section;
- requirements bullet count is below a threshold;
- `## Non-Goals` lacks a few flagged keywords.

This misses structured/numbered requirements, surveyed-file breadth, acceptance-criteria volume, trust/provenance/freshness semantics, parser/protocol boundaries, and cross-skill orchestration risk.

## Goal

Replace or augment the shallow deterministic heuristic with a deeper, more thoughtful recommender that uses deterministic hard triggers plus an LLM adjudication step for ambiguous cases. The recommender should fail safe to deep workflow when it cannot confidently classify the work as fast-lane-suitable.

## Recommended design

Use a hybrid decision model:

1. **Deterministic hard triggers → deep workflow**
   - many surveyed/touched files;
   - multiple skills/agents/subsystems affected;
   - parser/protocol/artifact-handoff/provenance/trust-boundary changes;
   - freshness, fallback, validation, migration, security, compatibility, or orchestration semantics;
   - many acceptance criteria or a large requirement surface;
   - changes to git/commit/worktree/branch-completion behavior;
   - explicit need for dependency decomposition, parallel tasks, verifier gates, or full integration-test reconciliation.

2. **Deterministic obvious-small triggers → fast lane**
   - localized change, likely 1–3 files;
   - few requirements / acceptance criteria;
   - no trust/protocol/orchestration semantics;
   - no broad parser compatibility concerns;
   - no cross-skill or multi-agent behavior.

3. **LLM adjudication for ambiguous cases**
   - Feed the LLM the spec/todo title, summary/goal, requirements, constraints, non-goals, tags, surveyed files, acceptance criteria, and any parsed deterministic signals.
   - Require strict JSON output, for example:

     ```json
     {
       "recommendation": "fast-lane|deep-workflow",
       "confidence": "low|medium|high",
       "rationale": "one-line rationale",
       "risk_factors": ["..."],
       "fast_lane_fit": ["..."],
       "deep_workflow_fit": ["..."]
     }
     ```

   - If the LLM call fails, output is malformed, or confidence is low, recommend `deep-workflow`.

## Implementation notes

- Preserve `recommend-workflow.py` as the machine-readable helper invoked by `agent/skills/define-spec/SKILL.md` Step 8, or replace it with a new helper with the same stable stdout/stderr JSON contract.
- The helper may need to accept both spec paths and todo IDs/content, depending on how much context is available at recommendation time.
- Consider adding an explicit `mode` / `source` field to output, e.g. `deterministic_deep`, `deterministic_fast`, `llm`, or `fallback_deep`.
- Keep the rendered Step 8 menu simple, but make the rationale richer and more truthful.
- Do not let an LLM recommendation silently override deterministic hard safety triggers.

## Regression example

For TODO-40e342b9 / `docs/specs/2026-05-11-harden-workflow-boundaries.md`, the recommender should recommend `deep-workflow` with a rationale like:

> spans multiple workflow skills and parser/protocol boundaries, includes trust/freshness validation semantics, and has many acceptance criteria across independent subsystems

The current output is wrong:

```json
{
  "recommendation": "fast-lane",
  "rationale": "no Approach section, 3 requirements (threshold 6), Non-Goals clean"
}
```

## Tests / acceptance criteria

- Existing fast-lane-fit fixture still recommends fast lane.
- Existing explicit deep fixtures still recommend deep workflow.
- Add a fixture based on `docs/specs/2026-05-11-harden-workflow-boundaries.md` or a reduced equivalent; it recommends deep workflow.
- Structured/numbered requirements and acceptance criteria are counted or otherwise considered; the helper no longer relies only on top-level `- ` bullets under `## Requirements`.
- Cross-skill/parser/protocol/trust-boundary language triggers deep workflow deterministically or through high-confidence LLM adjudication.
- LLM failure, malformed JSON, or low confidence falls back to deep workflow.
- Step 8 documentation in `agent/skills/define-spec/SKILL.md` reflects the deeper recommendation behavior and fallback semantics.
