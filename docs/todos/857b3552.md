## Context

While validating `docs/plans/2026-05-09-harden-workflow-parsers-against-markdown-like-content-in-embedded-payloads.md`, the deployed `~/.pi/agent/skills/execute-plan/scripts/extract-plan-tasks.py` reported missing `## Dependencies` and `## Risk Assessment` sections even though they were present.

Root cause: the plan contained outer triple-backtick example fences that themselves included inner triple-backtick fences. The current fence scanner treated an inner fence as the closer for the outer fence, then later treated the real outer closer as a new opener that ran to EOF. That made later top-level sections invisible to validation.

We patched the plan locally by changing the affected outer example fences to `~~~`, which validates cleanly against both the deployed script in `~/.pi/agent` and the repo copy.

## Long-term fix options

1. **Generation-side hardening (preferred)**
   - Update Generated Plan / planner outputs so any example block that contains triple backticks uses a different outer fence marker or a longer fence length.
   - Simple rule: choose `~~~` when embedding triple-backtick content; otherwise choose a fence length strictly longer than any same-marker run inside the payload.
   - This matches markdown expectations and avoids ambiguous source text.

2. **Validation-side better failure mode**
   - Teach `extract-plan-tasks.py` to detect ambiguous same-marker nested fences in plan prose/examples and emit a targeted protocol error instead of a misleading `missing_required_section`.
   - Example error shape could include line numbers and a remediation hint like: "example fence contains nested same-marker fence; switch outer fence to `~~~` or longer backticks".

3. **Plan lint / preflight check**
   - Add a lightweight lint pass in `generate-plan` / `refine-plan` / `execute-plan` preflight that scans for ambiguous fenced examples before execution begins.
   - This could auto-rewrite the outer fence safely or stop with a precise warning.

4. **Deeper parser change (optional, likely lower ROI)**
   - Revisit whether the shared fence logic should handle this class of malformed/ambiguous markdown more defensively.
   - Even if full recovery is undesirable, it should avoid silently swallowing the rest of the file.

## Suggested next step

Implement option 1 plus option 2: prevent ambiguous fences at generation time, and make validation failures precise when malformed examples still slip through.
