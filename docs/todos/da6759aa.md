## Goal

Make executable plan validation tolerant of semantically equivalent Markdown section labels, and ensure reviewed/generated plans cannot later fail `execute-plan` for irrelevant syntactic reasons such as `**Goal:**` versus `**Goal**:`.

## Context

A reviewed plan in `pi-interactive-subagent` contained these top fields:

```markdown
**Goal:** ...
**Architecture summary:** ...
**Tech stack:** ...
```

but `agent/skills/execute-plan/scripts/extract-plan-tasks.py` currently accepts only:

```markdown
## Goal
```

or:

```markdown
**Goal**:
```

for the required sections. Because the colon was inside the bold marker instead of after it, `execute-plan` stopped with:

```json
{
  "errors": [
    { "kind": "missing_required_section", "section": "goal" },
    { "kind": "missing_required_section", "section": "architecture_summary" },
    { "kind": "missing_required_section", "section": "tech_stack" }
  ]
}
```

The content existed; the failure was a parser/reviewer compatibility gap.

## Desired scope

- Relax required-section detection in `extract-plan-tasks.py` to accept equivalent bold-label forms, including at least:
  - `**Goal**: ...`
  - `**Goal:** ...`
  - `**Architecture summary**: ...`
  - `**Architecture summary:** ...`
  - `**Tech stack**: ...`
  - `**Tech stack:** ...`
- Keep current support for `## Goal`, `## Architecture summary`, and `## Tech stack` sections.
- Add regression coverage for the exact incompatibility above.
- Add or tighten a generate/review-time guardrail so a plan that has passed review is also executable by `extract-plan-tasks.py` before it is handed to `execute-plan`.

## Acceptance criteria

- `extract-plan-tasks.py --plan <plan>` succeeds when the required sections are expressed as `**Goal:**`, `**Architecture summary:**`, and `**Tech stack:**` with non-empty inline bodies.
- Existing accepted forms still pass.
- Regression tests cover both colon-outside-bold and colon-inside-bold forms.
- The plan generation/refinement workflow runs the same executable-plan validator, or an equivalent shared validator, before declaring a plan reviewed/ready.
- Validation failures for truly missing required content remain strict and actionable.

## Notes

This belongs in `pi-config` because the validation logic and workflow skills live under `agent/skills/`. The fix should avoid broad Markdown parsing changes unless needed; this is primarily about normalizing required section labels at the workflow boundary.
